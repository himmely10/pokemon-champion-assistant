# 伤害对照与培养点统计

本轮按用户反馈将默认页面改成招式矩阵，双方资料增加属性克制。原伤害公式与规则提交未变。

## 产品口径

- 我方使用明确选中的预存队伍及成员；四个槽位对应四行。
- 出招比较列：零耐久（无减防性格）、HP 32＋防御 32＋增防性格、HP 32＋特防 32＋增特防性格，以及双打采用率前三的培养点分配。两种满耐久各留两点到另一防御，总点数 66。
- 受击比较列：零输出、攻击 32＋加攻击性格、特攻 32＋加特攻性格，以及相同的常用培养点分配。两种满输出余点为速度 32／HP 2。
- 基准是固定特性、道具和场况下的参考，不宣称覆盖全部机制的全局最大／最小。特殊取攻防值招式逐列调用原引擎，不按招式大类拼出一个假极值。
- 每格是一套完整假设下的随机 HP 与百分比范围。常用分配可与独立统计的最常见性格组合为显式假设，但不宣称联合采用率。修改原分配后撤下其采用率。
- 表格首列悬浮招式说明；伤害格悬浮条件，点击查看完整配置／随机结果；切换方向同时切换详情。

## 来源与解析

参考 [OP.GG 大狃拉资料页](https://op.gg/zh-cn/pokemon-champions/pokedex/sneasler)。公开页面默认可能是单打，因此程序仅读取 `detailData.doubleDetail`。

`training[].spread` 是六个 **十六进制字节**，顺序 HP／攻击／防御／特攻／特防／速度。例如 `10-14-00-00-00-1e` 对应 16／20／0／0／0／30，而非按十进制字面值处理。校验六项长度、单项 0–32、总点数不超过 66、采用率有效性和重复分配。

`natures[]` 使用 `lookupData.natures` 解析独立性格统计；培养点对象不携带性格联合概率。保留赛季、双打模式、形态合并标记、来源更新时间及抓取时间。

日常仍运行 `scripts/update_usage_data.py --if-due`，统计功能版本升级后旧快照会补做一次同步。`--reparse-cache` 可离线重解析已缓存的同赛季、同参数公开响应；还要求来源时间与原招式率一致，不改写旧抓取时间。本轮由该命令为当前 245 个统计身份补充培养点／性格字段，没有将旧缓存伪装为新联网抓取。下一次正常日更继续同步这些字段。

## 属性克制

`config/type_chart.json` 从固定 Smogon Champions 提交 `e7fd7e59f3eef7ea42fba3c8b83261cb4a14109d` 的 generation 0 属性表导出，来源与 MIT 许可见 `damage_engine/vendor/smogon-calc/PROVENANCE.json` 和 `LICENSE`。`champion_assistant/type_matchups.py` 对当前形态的两种防守属性相乘。

用户截图的大狃拉期望：超能力 4×，地面／飞行 2×，虫 ¼×，草／格斗／毒／岩石／恶 ½×；另验证喷火龙与 Mega X 的飞行免疫变化。属性表明确排除特性、道具和临时属性变化。

## 状态与验证

保留原队伍选择、修订检查与迟到结果撤销。培养点／性格数据更新时重建默认情景并提示；仅招式率刷新或数据未变时保留手工情景输入，撤下旧结果。

新增用例位于 `tests/test_damage_comparison.py`，UI 回归位于 `tests/test_damage_ui.py`；覆盖十六进制解析、超限、缓存时间保留、培养点采用率与性格分离、两个方向的基准、四行招式矩阵、方向详情、属性相克、未知性格和更新后的情景失效。主窗口窄屏排版使用布局的按宽度计算高度，避免新增属性块覆盖种族值／速度表。

界面演示图：`artifacts/damage/outgoing-comparison.png`、`artifacts/damage/incoming-comparison.png`。示例使用演示预存烈咬陆鲨对大狃拉，不写入用户的队伍数据库。
