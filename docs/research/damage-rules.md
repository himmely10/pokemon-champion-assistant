## 能力值与输入

50 级 Champions：HP = 种族值 + 培养点 + 75（基础 HP 为 1 的特殊情况仍为 1）；其他能力 = floor((种族值 + 培养点 + 20) × 性格修正)。培养点直接传给 generation 0；不转换为传统 EV，不套用 252／510。

## 机制支持表

| 机制 | 本版处理与验证程度 |
|---|---|
| 常规物理／特殊、85–100 随机、本系、克制／免疫 | 接入；上述独立预期通过 |
| 能力等级、灼伤、晴天、生命宝珠、帮助、要害、反射壁、守住 | 接入；有独立范围基准 |
| 群攻有效目标数 | 接入；本地小补丁；单目标不改变双打墙修正 |
| 固定伤害 | 地球上投／黑夜魔影等快照实现及搏命；地球上投有独立基准 |
| 速度／体重／当前 HP／状态相关变威力 | 采用快照已有实现，例如陀螺球、打草结、喷火、祸不单行；未逐一做真实游戏伤害验证 |
| 扫墓 | 根据输入的倒下同伴数设置 50×(1+n)；未提供倒下次数历史或复活推演 |
| 其他快照支持的特性／道具／天气／场地 | 接入显式输入；不声称全部组合经过独立验证；无天气／场地自动推断 |
| 多段招式 | 暂不计算，等待段数情景；亲子爱由引擎分别返回两击随机集合，范围为两击合计，不给联合概率 |
| 反击／镜面反射／金属爆炸／复仇、莽撞／愤怒之牙、一击必杀等 | 本版明确拦截，不把缺实现的 0 当作免疫 |
| 愤怒之拳、围攻、以牙还牙、跺脚、流星光束／电光束等 | 依照 bridge 的显式名单拦截，等待历史、顺序或使用阶段输入与验证 |
| 复制 | 普通形态须明确选择实际复制到的特性，或未触发／无效果假设；不推断双打复制目标。Mega 使用对应形态特性 |
| 接收／化学之力／变幻自如／自由者／变色／变身者 | 暂停计算；可明确建立“无特性效果”简化假设 |
| 节拍器道具 | 缺连续次数输入，暂停计算 |
| 变化招式 | 无直接伤害，不计算状态效果或辅助价值 |
| 命中、追加效果、反伤、回复、整回合、KO 综合概率 | 未实现；结果以招式成功命中、使用条件成立为条件 |

公开引擎只是机制依据之一。本版没有完成 OP.GG 计算器交叉核对及真实游戏的逐机制伤害验收，U13 的完整验收仍有这些待办，不能声称所有机制均已准确覆盖。

## 资料和结果生命周期

本地形态种族值／属性、招式类型／分类／固定威力与规则快照不一致时拒算，来源新增不会自动套用相近物种。未知能力点／性格／特性／道具不能默认为零或首个特性。明确的“无特性效果”使用专用标记阻止上游自动挑选物种默认特性。

一次请求保存完整输入、资料包 ID、规则 ID、明确选择的预存队伍及其修订、成员位置。按用户后续要求，当前直接引用所选预存队伍，不再以我方阵容匹配作为前置条件，也不提供我方本局手工培养配置入口；未保存草稿不参与计算。保存修订、切换选择或修改场况后撤销结果，异步完成后再次读取队伍并比较快照。结果在内存中供用户查看，当前没有战斗历史归档。

## 架构决定

计划原先拟用纯 Python；本轮改为 Python 情景与生命周期适配器 + 固定、MIT 授权的本地 Node.js Champions 引擎，避免另写一套复杂取整。唯一 vendored 机制补丁是 `isSingleTarget`，其余产品边界在桥接／适配层处理。源码、编译产物、锁文件及来源记录均在 `damage_engine`。
