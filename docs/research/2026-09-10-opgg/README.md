公开页面包含 Next.js 内嵌资料；本次从响应中的序列化记录提取、按 key 去重得到 **352 个 OP.GG 资料条目**，其中 **35 个带 `isNew`**。首屏只渲染少量分页行，不能用首屏行数判断完整性。这不是已验证的稳定 API；后续适配器需要完整性检查、保存响应样例及结构变化检测。

## 名单初步差异

`roster-comparison.json` 记录对本地 209 物种／361 形态的比较。按基础物种 ID 初筛得到 **22 个本地未覆盖候选**：

胖可丁、猫老大、大葱鸭、魔墙人偶、吞食兽、暴飞龙、坐骑山羊、具甲武者、轰擂金刚猩、闪焰王牌、千面避役、猾大狐、颤弦蝾螈、八爪武师、喵头目、葱游兵、啪嚓海胆、爱管侍、奥利瓦、怒鹦哥、獒教父、戟脊龙。

比较尚未穷尽地区、性别及超级形态差异，也未完成每个新条目的图标适配验证。站点的新标记包含本地已有巴布土拨，故不能把 35 条新标记等同 35 个新增物种；不同来源形态拆分也不同，不能直接用 352 减 361 计算新增量。

`regulation` 观察值含 M-A、M-B、M-C；候选记录出现 M-C，但本轮尚未证明这些标签与当前赛季及可用规则的完整对应。同步器应保存原值，并单独核验合法范围。

## 接入时必须处理的差异

- **身份与名称：** OP.GG 的页面序号、物种 ID、特殊形态 ID、slug 含义不同。Mega 与地区形态的 slug 与旧站不同，使用显式映射；保留项目既有简体主名称，以来源别名解决用字差异，不批量重命名现有目录。
- **事实与统计：** 属性／种族值／招式机制、合法招式池、模式使用率、社区完整配置分别存储。详情默认返回单打内容，本轮尚未核验双打统计的实际请求方式；不能仅凭切换按钮宣称取得双打数据。
- **配置与概率：** 常用招式、道具、性格、加点的分别使用率不代表整套配置的联合使用率。伤害应逐完整假设配置列随机范围，不拼出虚构的概率。
- **能力值单位：** 计算器显示总预算 66，详情可见 2/32/32 分配示例。这支持单独建模 Champions 培养点，但总上限、单项上限、合法性及能力值公式仍须游戏面板和独立规则验证；不可直接套传统系列 252/510 努力值。
- **图像覆盖：** 新站有资料不等于有与当前识别模板相同风格的图标。先验证图像适配，无法取得时允许查资料并标记识别模板待就绪。
- **来源可靠性：** 计算器用于界面参考及数值交叉检查，不能单独证明伤害算法正确；另行维护规则依据、独立预期和支持机制清单。

## 旧脚本的更新障碍

本次检查 `scripts/collect_pokemon.py` 和 `scripts/export_pokemon.py` 发现：已下载网页会直接复用、赛季 M-5 固定、中文名称依赖固定 JS 文件名、导出遍历历史详情缓存。这适合一次性下载与续传，但无法可靠检查新版本，也可能把历史缓存混入当前范围。

主计划的 U10/U11 将“重新检查版本”与“图片断点复用”分开，并规划参数化规则范围、响应重验证、差异报告、版本 manifest、原子发布／回滚，以及新对局重建识别器。它们是后续开发内容，本轮未实现同步脚本或改写正式数据。
