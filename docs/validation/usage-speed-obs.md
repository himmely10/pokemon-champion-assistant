## OBS 真实链路

只读取必要连接字段确认初始配置 `server_enabled=false`，端口 4455。用户启用后，以本机 OBS 配置认证，连接 OBS 32.2.2，取得「视频采集设备」3840×2160 图片。

随后通过实际 `MainWindow → ObsDialog.read_local → 后台读取源列表 → 选择视频源 → capture_obs` 验证了同样流程。结果写入 `artifacts/obs-validation/ui-result.json`，未输出密码，`config/local_ui.json` 仅保存主机、端口和源名称。

采集时 Switch 位于 Pokémon HOME 盒子，六槽位均待确认；此结果用于证明真实图像采集和不误认盒子，**不算 Champions 实际选队画面端到端验收**。界面对此显示切换到正确选队布局的提示。连接失败的直接原因已解决，后续可在选队画面继续采集验证。

## OP.GG 采用率

核验公开页面与其明确引用的 CDN 脚本，发现页面使用的两种只读 server action：`getPokemonTierRankingFormatAction`、`getPokemonTierRankedBattleDetail`。脚本在每轮开始时动态发现入口，调用参数显式指定语言、赛季和 `double`，不硬编码入口哈希。

首次完整同步 M-6 双打 **245 个统计身份，零失败**。快照 `pokemon/_usage/snapshots/usage-2f07df6ac656793277cf6187.json`，来源时间逐条记录。再次执行 `--if-due` 返回 `not_due`。

只读取 `doubleDetail.moves[].usagePercent`，通过响应中的 `lookupData.moves` 映射招式 ID。测试包含：不误用胜负招式数据；身份不匹配、重复项、超界百分比、缺双打字段拒收；已知 0% 与未知采用率排序不同；无率固定威力降序；Mega 未独立提供统计时不借用普通形态；原子快照校验；单项失败保留同赛季旧数据；大面积失败不发布；跨赛季不继承旧缺失项。

研究材料在 `docs/research/2026-09-11-usage-speed/`，包括公开页面、相关脚本和实际双打排名／详情 RSC 响应。原始数据都来自公开只读请求，不含 OBS 设置。
