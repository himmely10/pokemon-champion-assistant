# 桌面资料台验证 · 2026-09-11

后续 OBS 连接修复、真实截图、双打采用率及速度线的最新验证见 [后续验证记录](usage-speed-obs.md)。以下保留最初资料展示切片的验证过程；其中 OBS 未启用的状态已在后续修正中解决。

本次实现对手识别与只读资料界面，不代表完整 v0.2（双方识别、预存队伍、速度判断、伤害引擎）验收完成。

## 环境与自动测试

- Windows，官方 CPython 3.13.7 独立 `.venv-ui`；PySide6 6.11.2、obsws-python 1.8.0、pytest-qt 4.5.0。
- 全量命令：`.venv-ui/Scripts/python.exe -m pytest -q`，55 项通过，37.19 秒。
- 真实截图通过 Qt 拖入事件、后台线程和正式识别器完成，结果依次为：苍炎刃鬼、风妖精、巨金怪、来悲粗茶、烈咬陆鲨、姆克鹰。
- 已验证：普通与 Mega X/Y/Z 对照、预览不修改对手身份、缺少来源的形态不串联、伤害/变化分组、威力与命中缺失语义、搜索、点击详情、说明转义、当前槽位纠错、新输入失效、取消后丢弃迟到结果、设置文件不保存密码。
- OBS 适配器用协议替身验证四种只读请求、源列表、PNG 解码、错误处理与连接关闭；这不等于真实设备采集已通过。
- UI 图像位于 `artifacts/ui/desktop-preview.png` 和 `artifacts/ui/desktop-small.png`。小窗口通过滚动访问资料，避免固定高度组件重叠。
- 最后调整面板滚动布局后，针对小窗口与 Mega／招式交互的 2 项回归再次通过。

## 本机交互与 OBS

已启动可见的资料台并载入根目录示例，进程响应正常，六只识别成功，单次匹配约 5.03 秒（未含所有冷启动成本）。

检测到 OBS 正在运行；截至本轮检查，默认 `4455` 端口没有监听。已请用户启用 WebSocket 并在界面中填写连接信息、选择视频源，再采集一次。真实 Switch 画面采集尚未取得成功证据，需要继续设备联调；不能把协议替身测试或本地示例算作真实 OBS 验收。

目前只有一张真实选队截图，不能据此声称整体准确率达到 98%，也没有达到或验证计划中 P95 ≤3 秒的性能目标。
