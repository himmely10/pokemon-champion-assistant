# Champion Lab 设计系统

> 版本：1.0
> 平台：Windows 桌面端 / PySide6
> 产品定位：面向宝可梦双打玩家的对战识别、队伍管理和计算工作台
> 视觉概念：训练家对战终端（Trainer Battle Terminal）

## 使用方式

本文件是全局视觉与交互规范。开发具体页面前，先读取
`design-system/champion-lab/pages/` 下对应页面规范；页面文件只覆盖明确列出的规则，
其余规则继承本文件。

设计调节值：视觉差异度 7/10、动效强度 4/10、信息密度 8/10。

## 1. 品牌基础

### 1.1 品牌主张

Champion Lab 不是百科网站，也不是电竞直播皮肤。它是一台帮助训练家在对战前和回合间
快速作出判断的专业终端。

界面应同时传达三种感受：

- **有世界观**：阵容槽位、属性、对位、扫描等语言来自宝可梦对战场景。
- **可信赖**：数值、假设、来源和不确定性清楚呈现，不用视觉效果掩盖信息。
- **反应迅速**：一个屏幕只有一个主行动，关键结论在详细数据之前出现。

### 1.2 独特设计原则

1. **对位先于资料**：首屏先回答“谁在对谁、谁更快、谁更危险”，再展示百科信息。
2. **双方语义恒定**：我方始终使用训练家蓝，对手始终使用对手红；不可在别处交换含义。
3. **一个舞台，少量容器**：阵容板是主视觉。避免把所有内容切成同款白色圆角卡片。
4. **结论先于数字**：先显示“稳定击杀 / 乱数 / 无法二击”，再允许查看计算明细。
5. **活泼但不幼稚**：活力来自色彩、切角和精灵图，而不是卡通贴纸、Emoji 或过度弹跳。
6. **诚实表达未知**：识别置信度、资料缺失和计算假设必须可见，不伪装成确定答案。

### 1.3 品牌边界

- 不复制官方宝可梦 Logo、游戏菜单、字体或完整精灵球商标造型。
- Pokémon 图片只用于宝可梦身份和队伍信息，不作为无意义装饰。
- 应用自身使用 `Champion Lab` / `冠军对战实验室` 标识，保持独立产品身份。
- 对外发布前单独复核精灵图片、名称、数据来源与商标使用范围。

### 2.3 阵营与状态使用规则

- 蓝色只表达我方或主操作；红色只表达对手、风险或破坏性操作。
- 红绿不得单独承担“坏 / 好”的含义，同时配合文字或图标。
- 黄色只用于需要用户注意但尚未失败的状态，一屏最多出现三个高亮区域。
- 属性色只表达属性，不表达选中、错误或阵营。
- 禁用态通过低对比度、禁用语义和光标共同表达，不能只改变透明度。

### 2.4 属性色

保留项目现有 18 种属性色作为领域色板。属性徽标统一使用白色文字；若某属性色无法满足
4.5:1，则加深背景色或使用深色文字，而不是加阴影补救。属性徽标必须显示属性名称，
不得只显示颜色。

### 2.5 字体

| 角色 | 字体 | 字重 | 说明 |
|---|---|---:|---|
| 品牌英文 / 大数字 | `Bahnschrift SemiCondensed` | 600–700 | Windows 内置，竞技感用于 `CHAMPION LAB`、伤害百分比 |
| 中文标题与正文 | `Microsoft YaHei UI` | 400–700 | 与当前打包环境兼容，中文可读性稳定 |
| 数据列 | `Bahnschrift`, `Segoe UI` | 500–600 | 仅数值使用 tabular figures，不使用全局等宽字体 |

禁止把 JetBrains Mono、Consolas 等等宽字体用于所有正文。若未来打包字体，应优先评估
Noto Sans SC；字体文件、许可证和安装失败回退必须一并进入发行包。

| 令牌 | 字号 / 行高 | 用途 |
|---|---:|---|
| `type.display` | `32 / 40` | 首次使用页主标题，极少使用 |
| `type.hero` | `28 / 36` | 当前宝可梦、关键伤害结论 |
| `type.title` | `22 / 30` | 页面标题 |
| `type.section` | `17 / 25` | 一级区块标题 |

| `type.label` | `13 / 19` | 控件标签、次级操作 |

| `type.data.lg` | `24 / 30` | 伤害和速度关键数字 |
| `type.data.md` | `16 / 22` | 表格重点数字 |

正文默认左对齐。数值列右对齐，短标签居中。中文段落不做两端对齐；正文阅读宽度控制在
32–44 个汉字。

### 2.7 间距

基础单位为 4px：

| 令牌 | 数值 | 用途 |
|---|---:|---|
| `space.1` | `4` | 图标内部、小间隔 |
| `space.2` | `8` | 紧密控件、同组元素 |
| `space.3` | `12` | 组件内边距 |
| `space.4` | `16` | 常规容器内边距 |
| `space.5` | `20` | 密集页面区块 |
| `space.6` | `24` | 主区块分隔 |
| `space.8` | `32` | 页面级间隔 |
| `space.10` | `40` | 空状态和引导区 |
| `space.12` | `48` | 页面外边距 |
| `space.16` | `64` | 品牌级留白 |

同一组件不得出现任意值。密集表格允许 8px 垂直内边距，主按钮至少 10px 垂直内边距。

### 2.8 圆角、切角和边框

| 令牌 | 数值 | 用途 |
|---|---:|---|
| `radius.sm` | `4` | 表格单元、提示条 |
| `radius.md` | `8` | 输入框、按钮 |
| `radius.lg` | `12` | 页面面板 |
| `radius.xl` | `18` | 空状态、模态框 |
| `radius.pill` | `999` | 属性、状态徽标 |

阵容板和关键对位面板可使用 10–14px 的单侧切角，由 `QPainterPath` 绘制。切角是领域识别，
只用于舞台、阵营标题和当前对位，不能出现在每个按钮上。

常规边框 1px；选中边框 2px；键盘焦点环 2px，外偏移等效 2px。焦点环与相邻颜色对比度
至少 3:1。

### 2.9 阴影和层级

| 层级 | 阴影 | 用途 |
|---|---|---|
| `elevation.0` | 无 | 表格、内嵌区域 |
| `elevation.1` | `0 1 2 rgba(20,36,58,.08)` | 浮起按钮、当前槽位 |
| `elevation.2` | `0 6 18 rgba(20,36,58,.12)` | 下拉、浮层 |
| `elevation.modal` | `0 18 48 rgba(8,16,29,.24)` | 模态框 |

QSS 不擅长复杂阴影时，优先用表面颜色和边框建立层级，不强制模拟网页阴影。

### 2.10 图标与图像

- 系统图标使用同一套原创或 Lucide 风格 SVG：20px 基准、1.75px 描边、圆角端点。
- 一级导航图标 22px，工具栏 18px，状态图标 16px；不可混用 Emoji。
- 活跃导航可使用填充版本，其他同层图标保持线性风格。
- 宝可梦阵容图 56×56，详情图 88×88，空状态主视觉不超过 160×160。
- 图片始终保持宽高比和透明通道，禁止拉伸；为异步图片预留固定区域，避免布局跳动。
- 装饰性图标不进入无障碍焦点；独立图标按钮必须提供可访问名称和提示。

## 3. 应用框架

### 3.1 信息架构

一级导航固定为：

1. 对战台
2. 队伍仓库
3. 伤害计算
4. 资料库
5. 设置

“资料更新”“OBS 设置”“使用引导”和“关于”属于设置，不占一级导航。一级导航始终可达，
当前页面同时使用活动指示条、背景和字重表达，不能只改变颜色。

### 3.2 桌面布局断点

| 可用宽度 | 布局规则 |
|---|---|
| `≥1440` | 176px 完整导航；主舞台；320px 判断面板 |
| `1120–1439` | 72px 紧凑导航；主舞台；280px 判断面板 |
| `800–1119` | 72px 紧凑导航；右侧面板移到主舞台下方 |
| `600–799` | 顶部紧凑导航；单列内容；双方阵容各为 3×2 |

应用最小可用尺寸为 600×480。低于 800px 时优先保留：当前对位、主操作、结论；完整
招式表、来源和高级条件折叠到二级区域。主页面不得出现横向滚动；数据表自身可在必要时
滚动，但必须冻结名称列。

### 3.3 页面骨架

```text
┌──────────────┬─────────────────────────────────────────────┐
│ 品牌          │ 页面标题                 全局状态 / 设置    │
│ 一级导航      ├──────────────────────────────┬──────────────┤
│               │ 主任务舞台                    │ 判断 / 操作  │
│               ├──────────────────────────────┴──────────────┤
│ 版本 / 离线态 │ 二级资料与明细                               │
└──────────────┴─────────────────────────────────────────────┘
```

窗口顶部不再放一排同权重按钮。每个页面只允许一个主要 CTA；页面级次要操作进入工具栏，
低频操作进入更多菜单。

### 3.4 滚动与尺寸

- 页面只保留一个主要纵向滚动容器，避免主窗口、左右面板和内部详情同时滚动。
- 固定头部和底部状态栏必须为内容预留空间，不能遮挡键盘焦点。
- 表格可独立滚动；鼠标滚轮在表格边界继续传递给页面时不得造成焦点丢失。
- 文本放大到 150% 时允许容器增高，不使用固定高度裁切正文。

## 4. 核心组件

### 4.1 按钮

| 类型 | 使用场景 | 高度 | 表现 |
|---|---|---:|---|
| Primary | 每页唯一主行动 | 40 | 训练家蓝底、白字 |
| Secondary | 同级辅助行动 | 40 | 白色/暗色表面、强边框 |
| Quiet | 工具栏和低频操作 | 36 | 透明底，悬停时出现状态层 |
| Danger | 删除、清空 | 40 | 危险红；与主行动保持至少 16px 间距 |
| Icon | 紧凑工具 | 36×36 | SVG 图标；必须有 accessibleName 和 tooltip |

状态必须覆盖 default、hover、pressed、focus、disabled、loading。Pressed 只改变背景、边框或
轻微内阴影，不移动组件边界。异步按钮在运行时禁用重复触发，并将文本改成具体进行状态，
例如“正在识别…”。

### 4.2 输入框与选择器

- 高度 40px，标签始终可见，不能只依赖 placeholder。
- placeholder 只给例子，例如“例如：顺风队 M6”。
- 帮助文本位于字段下方；错误同时说明原因和修复方式。
- 默认在失焦或提交后校验，不在每次按键时弹错误。
- 搜索框可在输入 150ms 后过滤；清空按钮、最近项目和无结果状态均可键盘操作。
- 只读字段使用表面背景和“只读”说明，与禁用态区分。

### 4.3 徽标与标签

| 组件 | 结构 | 用途 |
|---|---|---|
| Type badge | 属性名 + 属性色 | 宝可梦与招式属性 |
| Status badge | 图标 + 状态文本 | 已连接、待确认、离线 |
| Verdict badge | 形状 + 结论文本 | 优势、均势、危险 |
| Condition chip | 文本 + 可选关闭按钮 | 顺风、能力等级、特性条件 |

标签不换行，集合空间不足时先整体换行；仍不足时显示可操作的“还有 n 项”。禁止只用颜色表示
状态，也不使用全大写英文作为装饰标签。

### 4.4 表格

- 表头高度 38px，数据行 40px；密集模式最低 34px。
- 名称列左对齐，数值列右对齐，状态和短标签居中。
- 行悬停和选中必须不同；选中行增加 3px 阵营色侧条。
- 排序表头显示方向图标，并通过可访问名称说明排序方式。
- 超过 50 行时启用虚拟化或 Qt 原生 model/view，不逐个创建复杂单元控件。
- 空表格不显示空网格，改为说明原因和下一步操作。
- 图表或伤害条必须同时提供可复制的数值文本。

### 4.5 标签页

标签页仅用于同一对象的平级视图，如“结论 / 速度 / 招式 / 属性”。一级导航不可再使用
标签页。选中标签使用底部 3px 指示条、字重和前景色三重表达。

### 4.6 面板与卡片

- 页面级面板使用 `radius.lg`，内部资料区尽量通过留白和分隔线组织。
- 只有可点击对象才提供明显 hover 状态；静态容器不做悬浮效果。
- 不在同一屏幕堆叠超过三个视觉层级。
- 关键舞台允许切角；普通资料卡保持直角或 8px 小圆角。

### 4.7 对话框与抽屉

- 主要工作流不得依赖模态框；模态框只用于确认、短配置和错误恢复。
- 对局上下文中的详细资料使用右侧抽屉，宽度 360–480px。
- 模态框必须有标题、清晰关闭按钮、Esc 关闭路径和初始焦点。
- 有未保存内容时关闭必须确认；破坏性确认按钮写清对象，例如“删除队伍”。

### 4.8 状态消息

- 成功：简短确认，不抢焦点，3–5 秒后消失；重要结果保留在页面中。
- 警告：说明仍可继续的影响和下一步。
- 错误：说明发生了什么、可能原因以及“重试 / 修改设置”等恢复行动。
- 后台更新：放入全局状态中心，不覆盖当前对局状态。
- Toast 不替代字段内错误，也不弹出阻塞式“成功”消息框。

## 5. 对战专用组件

### 5.1 Battle roster / 阵容板

阵容板是全产品唯一可以大胆表达品牌的组件。双方各六个固定槽位，中间有明确 VS 轴线。

槽位状态：

| 状态 | 视觉 | 文案/语义 |
|---|---|---|
| Empty | 虚线轮廓 + 编号 | 等待识别 |
| Scanning | 黄色进度弧 + 稳定占位 | 正在识别第 n 个位置 |
| Confirmed | 精灵图 + 名称 + 属性点 | 已识别 |
| Review | 黄色边框 + `!` 图标 | 需要确认 |
| Corrected | 小铅笔图标 + 文本 | 已手动修正 |
| Selected | 2px 阵营边框 + 外光环 | 当前对位 |
| Unavailable | 降低对比 + 原因文本 | 资料不可用 |

`Review` 不能用低置信度数字吓到普通用户；默认显示“需要确认”，详细置信度放在 tooltip 或
详情中，并明确“相似度不是正确率”。

### 5.2 Matchup focus / 当前对位

必须同时显示：我方名称和图片、对手名称和图片、双方属性、速度关系摘要以及打开完整计算的
主按钮。选择任一阵容槽位时只替换内容，不重排整个页面。

### 5.3 Verdict / 判断结论

允许的顶层结论词汇：

- **我方更快 / 对手更快 / 速度相同 / 条件不足**
- **稳定击杀 / 高概率击杀 / 乱数击杀 / 无法击杀**
- **免疫 / 抵抗 / 等倍 / 弱点 / 四倍弱点**

每个结论必须附带计算条件入口。不得单独显示“优势”而不说明优势来自速度、属性还是伤害。

### 5.4 Damage range bar / 伤害范围条

- 轨道代表 0–100% 当前 HP；最小值到最大值使用实心范围段。
- 超过 100% 的部分用箭头或文本表示，不扩展轨道宽度。
- 关键阈值 50% 和 100% 有低强调刻度。
- 范围段上方显示 `最低%–最高%`，旁边显示击杀判断。
- 条件或随机数不足时使用斜纹和“估算”文本，不能只改变透明度。

### 5.5 Speed comparison / 速度对照

默认展示当前实际条件下的一个结论和两个数值，而不是先给六档大表。完整速度线放入展开区。
顺风、能力等级和条件特性使用 condition chip，并在修改后立即重新计算。

### 5.6 Type matchup / 属性克制

按“弱点 / 抵抗 / 免疫”分组，每组显示属性徽标和倍率。空组显示“无”，不要留下空白。
四倍弱点使用倍率文本和双层边界，不使用闪烁。

### 5.7 Move row / 招式行

首层信息顺序：招式名、属性、分类、采用率、威力、命中。伤害计算语境下优先显示伤害范围和
击杀判断。悬停只能补充信息，选择、打开详情和查看说明必须支持点击与键盘。

## 6. 交互与动效

### 6.1 动效令牌

| 令牌 | 时长 | 曲线 | 用途 |
|---|---:|---|---|
| `motion.instant` | `0ms` | — | 减少动态效果模式 |
| `motion.fast` | `100ms` | OutCubic | 按压、hover、焦点 |
| `motion.base` | `160ms` | OutCubic | 内容替换、标签切换 |
| `motion.emphasis` | `240ms` | OutCubic | 抽屉、页面层级变化 |
| `motion.scan` | `360ms` | InOutCubic | 单次扫描段；槽位间隔 45ms |

动效只表达因果：点击槽位后当前对位交叉淡入；开始识别后扫描弧依次移动；完成后结果稳定
落位。一屏最多两个非用户触发的动效。数据表不弹跳、不逐行飞入。

所有动画必须可打断，正确状态不能依赖动画结束事件。读取系统减少动态偏好（平台支持时），
并在设置中提供“减少动态效果”覆盖项；启用后直接渲染最终状态。

### 6.2 键盘模型

- `Ctrl+O`：打开截图。
- `Ctrl+Shift+O`：从已配置 OBS 捕获。
- `Ctrl+K`：全局搜索宝可梦。
- `Ctrl+1…5`：切换一级页面。
- `←/→`：同一阵营槽位间移动；`↑/↓`：在双方阵营间移动。
- `Enter`：选择槽位或打开当前详情；`Esc`：关闭抽屉/模态框。
- `F11`：伤害计算全屏；保留当前项目行为。

Tab 顺序必须与视觉顺序一致。页面切换后焦点移到页面标题或首个主操作；任何固定栏、Toast
和抽屉都不能遮挡当前焦点。

### 6.3 异步反馈

- 低于约 300ms 的操作不闪现进度组件。
- 截图识别等长操作立即改变按钮状态，并显示稳定的六槽位扫描反馈和可取消入口。
- 取消后说明“已取消，本次迟到结果不会应用”。
- 网络更新必须显示离线降级：当前资料仍可用、更新时间以及下一次恢复方式。

## 7. 内容语言

界面使用简体中文、主动语态和一致动词。

推荐：

- “开始识别”“重新识别”“保存队伍”“打开伤害计算”“修正这个位置”
- “未找到可识别的六只宝可梦。请使用完整的 Champions 选队截图。”
- “OBS 认证失败。请检查端口和密码后重试。”

避免：

- “提交”“确定”“操作失败”“数据异常”等缺少对象或恢复路径的泛化词。
- “01 / 02 / 03”装饰编号；只有确实属于连续向导时才使用步骤编号。
- 标题全部大写、每个区块都有眉题、箭头作为按钮装饰。

## 8. 可访问性基线

- 正文与背景对比度至少 4.5:1；大文本和非文本边界至少 3:1。
- 所有交互控件有 2px 可见焦点环；不可移除系统焦点而没有替代。
- 桌面指针模式目标高度至少 36px，主要操作 40px；触屏模式扩大到至少 44×44px。
- 颜色永远配合文本、形状或图标表达信息。
- 拖入截图必须提供“打开截图”按钮和键盘入口。
- 宝可梦图像的可访问名称使用“宝可梦：名称”；纯装饰背景从无障碍树隐藏。
- 状态变化用完整短句宣布，但不抢焦点，例如“已识别 5 个位置，1 个需要确认”。
- 支持系统字号 100%、125%、150%；关键文本不截断，长名称优先换行或提供完整 tooltip。
- 表格、下拉和模态框均需在纯键盘操作下完成主要任务。

## 9. 性能基线

- 识别和伤害计算继续运行在工作线程，主线程单帧工作尽量小于 16ms。
- 宝可梦缩略图按显示尺寸缓存；页面外图片延迟创建，切换资料包时清理对应缓存。
- 固定图片容器尺寸，避免结果返回后布局跳动。
- 超过 50 行的数据使用 Qt model/view 和过滤代理模型。
- 搜索输入 150ms 防抖；窗口 resize 和 splitter 变化合并处理。
- 加载状态不清空上次仍然有效的资料，使用覆盖状态说明正在刷新。

## 10. PySide6 实现映射

| 设计概念 | PySide6 建议 |
|---|---|
| 语义令牌 | `theme.py` 中 `ThemeTokens` 数据类或字典，由主题生成 QSS |
| 页面导航 | `QStackedWidget` + 固定 `NavigationRail` |
| 阵容板 | 自定义 `BattleRosterWidget` / `RosterSlot`，必要效果用 `QPainter` |
| 页面布局 | `QGridLayout`，断点时重排，不复制页面实例 |
| 长列表 | `QAbstractTableModel` + `QSortFilterProxyModel` + `QTableView` |
| 抽屉 | 主布局内可动画宽度的详情容器；减少动效时直接切换可见性 |
| 状态 | Qt dynamic property，例如 `role=trainer`、`status=review`、`selected=true` |
| 图标 | SVG 资源 + `QIcon`；主题色版本由资源或绘制层控制 |
| 无障碍 | `setAccessibleName`、`setAccessibleDescription`、合理 focusPolicy 和 tab order |

QSS 负责颜色、字体、边框和控件状态；复杂切角、扫描弧、伤害区间和阵容连接线由绘制组件
负责。避免在 QSS 中通过大量选择器覆盖制造 specificity 冲突。

## 11. 验收清单

### 视觉

- [ ] 首屏最醒目的元素是双方阵容或当前任务，不是品牌标题。
- [ ] 我方蓝、对手红和属性色没有语义冲突。
- [ ] 静态容器没有无意义 hover、阴影或动画。
- [ ] 所有图标来自同一 SVG 语言，没有 Emoji。
- [ ] 600、800、1120、1440、1920 宽度下没有主页面横向滚动。

### 交互

- [ ] 每页只有一个主要 CTA，异步状态不可重复提交。
- [ ] 纯键盘可以完成截图导入、选择对位、打开计算和保存队伍。
- [ ] Tab 顺序、焦点恢复和 Esc 路径符合视觉层级。
- [ ] 拖放、悬停和右键功能都有显式按钮或键盘替代。
- [ ] 页面切换保留阵容选择、筛选、滚动和计算条件。
- [ ] 错误信息包含原因、影响和恢复行动。

### 可访问性与主题

- [ ] 正文 4.5:1、界面边界 3:1、焦点状态 3:1 均实际测量。
- [ ] 100%、125%、150% 字号下没有固定高度裁切。
- [ ] 减少动态效果下直接呈现最终状态且所有功能可用。
- [ ] 浅色与暗色的 hover、pressed、focus、disabled、selected 均分别检查。
- [ ] 选中、危险、成功和待确认均不只依赖颜色。

### 性能与数据

- [ ] 长列表使用 model/view，没有为每行创建复杂子控件。
- [ ] 加载过程保留稳定尺寸，不出现明显布局跳动。
- [ ] 图表有文本数值，伤害结论可追溯到条件和明细。
- [ ] 离线、资料过期、识别不足和空队伍均有明确下一步。

## 12. 明确禁止的设计

- 霓虹紫色电竞模板、全局暗黑 HUD、玻璃拟态和持续发光边框。
- 精灵球红白配色铺满整个应用。
- 全局等宽字体、全大写标签、过小灰字和长段居中正文。
- 所有内容都放入同样圆角、阴影和 hover 的卡片。
- 雷达图表示种族值、饼图表示招式采用率、纯红绿表示输赢。
- 自动轮播、背景视频、装饰性粒子、连续呼吸动画。
- 识别完成后仍永久占据大面积的截图上传区。
- 用阻塞式消息框报告普通成功，或让错误只显示“失败”。
