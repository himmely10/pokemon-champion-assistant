# 队伍仓库页面规范

> 继承 `../MASTER.md`。本页替代以弹窗为中心的队伍配置流程。

## 页面目标

快速找到、创建、导入和校验预存队伍，并让六名成员的培养信息具有清晰的完成状态。

## 布局

```text
┌──────────────────────────────────────────────────────────────┐
│ 队伍仓库                   搜索队伍      导入截图   创建队伍 │
├──────────────────┬───────────────────────────────────────────┤
│ 最近使用          │ 顺风队 M6                      已保存     │
│ ○ 顺风队 M6       │ [成员1][成员2][成员3][成员4][成员5][成员6]│
│ ○ 空间队          ├───────────────────────────────────────────┤
│                  │ 当前成员配置                              │
│ 其他队伍          │ 宝可梦 / 努力值 / 性格 / 特性 / 道具 / 招式│
└──────────────────┴───────────────────────────────────────────┘
```

- 左栏 240–280px，按最近使用和其他队伍分组，不使用 6 个成员标签页作为首层导航。
- 页面唯一 Primary 为 `保存队伍`；未修改时禁用并显示“所有更改已保存”。
- `创建队伍` 和 `导入截图` 为 Secondary；重命名、复制和删除进入更多菜单。
- 六个成员槽位始终在表单上方可见，完成状态由图标、文本和边界共同表达。

## 成员槽位状态

- 空：`添加成员`，虚线边界。
- 未完成：显示宝可梦和“还缺 3 项”，黄色状态图标。
- 完成：显示宝可梦、属性和“配置完整”。
- 当前编辑：训练家蓝 2px 边界和底部指示条。
- 图片导入待核对：显示“待核对”，不能直接标记为完成。

## 表单结构

表单按语义分三组，并支持折叠但默认展开：

1. **身份**：宝可梦 / 形态。
2. **培养**：等级、能力值或培养点、性格、特性、道具。
3. **招式**：四个有序招式槽位。

每项都有可见标签。培养点显示 `已分配 60 / 66` 和剩余量；超限错误紧邻相关字段，并在
顶部出现可聚焦的错误摘要。完整登记模式同时检查六只槽位，错误摘要可跳到成员和字段。

## 截图导入流程

这是明确的连续流程，允许使用步骤编号：

1. 选择能力页截图。
2. 选择状态页截图。
3. 核对识别草稿。
4. 保存到队伍。

本地图片与 OBS 是输入方式，不是两套不同向导。核对页并排显示“识别值”和“最终值”，
差异使用文本和图标标记；未核对字段不能悄悄写入正式队伍。

## 保存和删除

- 长表单自动保存草稿，但只有点击 `保存队伍` 才发布到正式队伍。
- 关闭有未保存更改的页面时，提示“保存更改 / 放弃更改 / 继续编辑”。
- 删除使用确认对话框，按钮写“删除「顺风队 M6」”；成功后提供短时撤销。
- 队伍名称重复时说明冲突并建议修改，不能只报“保存失败”。

## 响应式

- 1120px 以下左侧队伍列表收成可展开栏。
- 800px 以下成员槽位变为 3×2，表单双列变单列。
- 600px 宽度仍保持标签与输入上下排列，不缩小字号或制造横向滚动。

## 验收重点

- 用户无需在六个标签页中逐一寻找未完成成员。
- 所有未保存、自动草稿、已正式保存状态均可区分。
- 截图识别结果必须经过明确核对，不被误认为准确的正式配置。
